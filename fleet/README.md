# Fleet Hub — private dashboard

A single private view of the whole `vector-*` fleet: one card per model repo with
its domain, live link, embedding dimension, architecture tag, maturity status, the
headline metric (with baseline and computed lift), a compact metrics list, and a
plain-language strengths / gaps note. `vector-unified` is marked as the keystone.

## Why it's private

`fleet/data/fleet.json` aggregates eval metrics from **every** model repo,
including the private ones (`vector-realty`, `vector-unified`). It therefore holds
private-model numbers and self-review notes that are not published anywhere. That
is why the dashboard lives here, in the private `vector-unified` repo, and is
**not** part of any deploy — see the top-level architecture: the live site is
served separately and this subtree is additive-only.

## How to view

The dashboard fetches `./data/fleet.json` at runtime, and browsers block
`fetch()` over `file://`, so open it via a static server rather than double-clicking
the HTML:

```bash
cd fleet
python3 -m http.server 8000
# then open http://localhost:8000/
```

(No build step, no dependencies, no CDNs — plain HTML/CSS/JS. It is theme-aware:
it follows your OS light/dark preference.)

## How to regenerate `data/fleet.json`

The data file is regenerated by `scripts/aggregate_fleet.py`, which reads each
model repo's committed eval JSON:

```bash
# Validate the committed fleet.json against the expected shape (no network):
python3 scripts/aggregate_fleet.py --offline

# Rebuild from the public repos' raw eval JSON (network):
python3 scripts/aggregate_fleet.py
```

Public repos are read over `raw.githubusercontent.com`. The private repos
(`vector-realty`, `vector-unified`) require an authenticated fetch or local paths
— see the comments at the top of `scripts/aggregate_fleet.py`. The script is pure
Python stdlib (`urllib` + `json`); no packages to install.
